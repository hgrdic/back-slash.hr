## How to start it

Dependencies are already installed.

1. **Add your Stripe key.** Open `.env` and replace `sk_test_...` with your test secret key from https://dashboard.stripe.com/test/apikeys. Checkout doesn't need the publishable key.
2. **Start the app:** run `npm run dev` and open http://localhost:3000.
3. **Sign up and buy a pack.** Use the test card `4242 4242 4242 4242` with any future expiry date, any CVC and any ZIP. You should land back on the dashboard with the new credits.

**Webhook (optional today):** credits are added even without it. When Stripe sends the user back, the dashboard checks the payment with Stripe and adds the credits. The webhook covers people who close the tab before that redirect, and you'll need it in production. To set it up:
```bash
brew install stripe/stripe-cli/stripe
stripe login
stripe listen --forward-to localhost:3000/api/webhooks/stripe
```
Paste the `whsec_...` value it prints into `STRIPE_WEBHOOK_SECRET` in `.env`, then restart `npm run dev`.

## How it works

- **Database:** SQLite in `app.db`, which is created automatically on first use and kept out of git. Delete `app.db*` to start over.
- **Accounts:** passwords are hashed with bcrypt, and login sessions use an httpOnly cookie.
- **Prices:** the two packs are defined only on the server in `lib/stripe.ts`. The browser just picks "small" or "large", so nobody can change the price.
- **Adding credits:** `fulfillCheckout` adds them only when Stripe says the payment is paid and the amount matches. It records each payment, so if the webhook and the redirect both arrive, the credits are only added once.
- **Generate:** taking the credit is a single database update that only succeeds when the balance is at least 1, so clicking fast can't push it below zero.

Main files: `app/actions.ts` (sign up, log in, buy, generate), `app/dashboard/page.tsx`, `app/api/webhooks/stripe/route.ts` and `lib/`. The `README.md` has the same steps plus notes on going live. SQLite needs a persistent disk, so don't deploy it to Vercel as is.
