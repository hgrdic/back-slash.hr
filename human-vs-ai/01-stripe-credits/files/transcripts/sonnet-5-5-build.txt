## How to start it

1. Open `.env` in the project folder. I created it with placeholders, so replace `STRIPE_SECRET_KEY=sk_test_REPLACE_ME` with your Stripe test secret key. `SESSION_SECRET` is already set to a dev value.
2. Run:
   ```
   npm install
   npm run dev
   ```
3. Open http://localhost:3000, sign up, and buy credits. Use test card `4242 4242 4242 4242` with any future expiry and any CVC.

## What it does

- **Accounts:** Sign up and log in with email and password. Passwords are hashed with bcrypt, and the session is a signed httpOnly cookie.
- **Database:** SQLite, with the file `data.db` created automatically on first run.
- **Buying credits:** The dashboard has two buttons, 10 credits for $5 and 50 credits for $20. The prices live on the server, so the browser can't change them.
- **Generate:** Each click on "Generate" costs 1 credit and returns a random quote. The deduction is a single atomic update, so double clicks can't push the balance below zero. The dashboard shows the credit balance.
- **Crediting payments:** Credits are added when Stripe sends the user back to the dashboard after paying. The webhook at `/api/webhook` also adds them, in case someone closes the tab first. Each Stripe session is stored, so a payment is counted only once even if both paths fire.

## Webhook (optional)

The webhook needs the Stripe CLI running, because Stripe can't reach localhost otherwise:

```
stripe listen --forward-to localhost:3000/api/webhook
```

Copy the `whsec_...` value it prints into `STRIPE_WEBHOOK_SECRET` in `.env` and restart. Without it, credits are still added on the return redirect.

The `README.md` has the same steps. I haven't made a git commit.
